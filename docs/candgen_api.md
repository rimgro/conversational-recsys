# API кандгенов (контракт)

BM25 и HNSW работают на VPS двумя отдельными процессами, наша часть (`recsys/retrieval/remote.py`) вызывает их по HTTP.
Этот файл — единственное, что их связывает: код каждой части можно менять как угодно, пока соблюдается контракт.

| Сервис | Адрес | Код | Запуск |
|---|---|---|---|
| BM25 | `http://<IP>:8001` | `bm25/` | `deploy/recsys-bm25.service` |
| HNSW | `http://<IP>:8002` | `hnsw/` | `deploy/recsys-hnsw.service` |

Ключ: если на сервисе задан `BM25_API_KEY` / `HNSW_API_KEY`, нужен заголовок `X-API-Key`. Пока ключей нет.
Id треков везде — `m4a_id` из `tracks_meta.parquet` (те же, что в каталоге нашей части).

## BM25 — `POST /bm25/search`

```json
{"words": ["rock", "indie"], "k": 200, "exclude_ids": ["..."], "index": "genres"}
```

| Поле | Тип | |
|---|---|---|
| `words` | список строк, до 256 | слова запроса (английские теги, латиница), регистр не важен |
| `k` | 1..1000 | сколько треков вернуть |
| `exclude_ids` | список строк, до 100 000 | не возвращать эти треки |
| `index` | `genres` (по умолчанию), `tags`, `title` | по какому полю искать |

Ответ: `{"ids": [...], "scores": [...], "index": "genres", "index_version": "..."}`, по убыванию `scores`.

`GET /health` → `{"status": "ok", "default_index": "genres", "indexes": {"<имя>": {"index_version", "n_items", ...}}}`.

## HNSW — `POST /hnsw/search`

```json
{"track_ids": ["..."], "weights": [1.0], "k": 200, "exclude_ids": ["..."], "index": "audio"}
```

| Поле | Тип | |
|---|---|---|
| `track_ids` + `weights` | списки одной длины, до 10 000; `weights` можно не передавать | запрос — взвешенное среднее эмбеддингов этих треков |
| `vector` | список чисел | вместо `track_ids`: готовый вектор запроса |
| `k`, `exclude_ids`, `index` | как у BM25; индекс по умолчанию `audio` (MuQ) | |

Нужно ровно одно из `track_ids` и `vector`. Ответ: `{"ids", "scores", "index", "index_version", "n_query_tracks"}`,
где `n_query_tracks` — сколько треков запроса нашлось в индексе.

`GET /hnsw/health` → `{"status": "ok" | "no_indexes", "default_index": "audio", "indexes": {"<имя>": {"index_version", "n_items", "dim", ...}}}`.

## Ошибки

| Код | Когда |
|---|---|
| 401 | ключ задан на сервисе, а заголовка нет или он неверный |
| 404 | неизвестный `index` |
| 422 | тело не по контракту (лишнее поле, превышен лимит, нет `track_ids`/`vector`) |
| 503 | HNSW запущен без индексов |

Наша часть при любой ошибке или таймауте пропускает источник (пустой список + предупреждение), остальные источники работают.

## Как менять

- Можно без согласования: добавить необязательное поле в ответ, новый индекс, поднять лимиты, менять внутренности
  (алгоритм, формат файлов индекса). `index_version` в ответе меняется при пересборке индекса.
- Сервисы отклоняют незнакомые поля запроса (`extra='forbid'`), поэтому новое поле запроса сначала добавляется
  в сервис, потом в клиент.
- Ломающее изменение (переименовать или удалить поле, поменять смысл) — новый путь `/v2/...`, старый живёт,
  пока клиент не переедет.
- Проверка контракта: `tests/test_remote.py` (клиент против поддельного сервиса и против настоящих `bm25/` и `hnsw/`),
  тесты в `bm25/tests` и `hnsw/tests` (сами сервисы).
