# API сервисов-кандгенов (контракт)

Сервисы живут отдельно от этого репозитория-ветки, наша часть (`recsys/retrieval/remote.py`) вызывает их по HTTP.
Этот файл — то, что их связывает: код каждой стороны можно менять как угодно, пока контракт соблюдается.

| Сервис | Код | Сейчас |
|---|---|---|
| BM25 | ветка `bm25-cards` (релиз v1.3) | развёрнут на сервере, адрес и ключ — `BM25_URL`, `BM25_API_KEY` |
| HNSW (текстовый поиск, EmbeddingGemma + LanceDB) | ветка `dev/hnsw`, релиз `hnsw-v1` | развёрнут на сервере, адрес и ключ — `HNSW_URL`, `HNSW_API_KEY` |

Поиск по аудио-эмбеддингам MuQ сервиса не требует: его считает наш источник `audio`.

Ключ: если на сервисе задан ключ, нужен заголовок `X-API-Key`. Id треков — `m4a_id` из `tracks_meta`
(те же, что в каталоге нашей части).

## BM25 — `POST /bm25/search`

```json
{"words": ["rock", "indie"], "k": 200, "exclude_ids": ["..."], "index": "cards"}
```

| Поле | Тип | |
|---|---|---|
| `words` | список строк, до 256 | слова запроса (английские теги, латиница), регистр не важен |
| `k` | 1..1000 | сколько треков вернуть |
| `exclude_ids` | список строк, до 100 000 | не возвращать эти треки |
| `index` | `cards` (по умолчанию) | индекс по всей карточке трека; `genres` и `tags` — старые имена того же индекса |

Ответ: `{"ids": [...], "scores": [...], "index": "cards", "index_version": "..."}`, по убыванию `scores`.

`GET /health` → `{"status": "ok", "default_index": "cards", "indexes": {"<имя>": {"index_version", "n_items", ...}}}`.

## HNSW — `POST /hnsw/search`

Текстовый семантический поиск: вектор запроса (`google/embeddinggemma-2`, 768 чисел) строит клиент, сервис ищет
ближайшие треки в LanceDB (текст трека — метаданные, теги, описание, лирика). Энкодера на сервере нет.

```json
{"vector": [0.012, -0.034, "... 768 чисел"], "k": 200, "exclude_ids": ["..."]}
```

| Поле | Тип | |
|---|---|---|
| `vector` | 768 чисел | вектор запроса EmbeddingGemma-2, L2-нормированный (как у индекса); `query` сервис больше не принимает — 422 |
| `k` | 1..1000, по умолчанию 20 | сколько треков вернуть |
| `exclude_ids` | список строк, до 100 000 | не возвращать эти треки |

Поля `index` нет (одна таблица); незнакомое поле — 422. Наш клиент строит вектор последней реплики сам
(`recsys/retrieval/query_embedder.py`, рецепт сервиса: `task: search result | query: <текст>` → EmbeddingGemma-2 → L2;
профиль пользователя не добавляется — ухудшает поиск). Если модель не загрузилась, источник `hnsw` пропускается.

Ответ: `{"ids": [...], "scores": [...], "items": [{"id", "title", "artist", "album", "year", "lang", "genres", "tags", "score"}],
"model", "release", "elapsed_ms"}`; `scores` — косинусная близость, по убыванию. При `k=200` — около 0.5 с и 117 КБ.

`GET /health` → `{"status": "ok", "release": "hnsw-v1", "n_items": 64016, "dimension": 768, "model", "device", "table_version", "indices"}`.

## Ошибки

| Код | Когда |
|---|---|
| 401 | ключ задан на сервисе, а заголовка нет или он неверный |
| 404 | неизвестный `index` |
| 422 | тело не по контракту (лишнее поле, превышен лимит; у HNSW — нет `vector` или прислан `query`) |

Наша часть при любой ошибке или таймауте пропускает источник (пустой список + предупреждение), остальные работают;
`evaluate.py --candgen` не начинает прогон, если `/health` не отвечает.

## Как менять

- Можно без согласования: добавить необязательное поле в ответ, новый индекс, поднять лимиты, менять внутренности
  (алгоритм, формат файлов индекса). `index_version` в ответе меняется при пересборке индекса.
- Сервис отклоняет незнакомые поля запроса (`extra='forbid'`), поэтому новое поле запроса сначала добавляется
  в сервис, потом в клиент.
- Ломающее изменение (переименовать или удалить поле, поменять смысл) — новый путь `/v2/...`, старый живёт,
  пока клиент не переедет.
- Проверка контракта со стороны клиента — `tests/test_remote.py` (поддельный сервис), со стороны сервиса —
  тесты в его ветке.
