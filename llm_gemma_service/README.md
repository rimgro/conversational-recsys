# Gemma в отдельном процессе

Эта папка содержит Python-клиент и запуск `llama-server`.
Веса `gemma-4-26B_q4_0-it.gguf`, CUDA-сборка, лог и состояние процесса остаются в
`/home/jupyter/project/llm/cuda122`. Копировать их в репозиторий не нужно.

## Подключение в DataSphere

Ноутбук первичной настройки (сборка CUDA 12.2, загрузка весов) удалён из ветки; он есть в истории git
(`git show 3fd1024:llm_gemma_service/gemma_datasphere_service.ipynb`). Подключение к пайплайну —
`configs/gemma.yaml` (`llm.type: gemma_service`, `explainer.type: llm`).

Сервис и пайплайн должны выполняться на **одной ВМ**, поскольку API слушает
`http://127.0.0.1:11435`. Общая папка проекта сама по себе этого не обеспечивает.
Если модель уже загружена, запрос сразу использует её. Холодный запуск происходит
при отсутствии сервера; загрузка в GPU занимает прежнее время.

## Из Python

Из корня репозитория:

```python
from llm_gemma_service import ensure_running, measure_request, measure_chat, status

ensure_running()  # подключится к готовому серверу либо запустит его
result = measure_request("Посоветуй музыку для работы.", max_tokens=128)
print(result["seconds"])  # запрос до полного ответа; время старта — result["startup"]

result = measure_chat([
    {"role": "system", "content": "You are a music assistant."},
    {"role": "user", "content": "Recommend calm jazz."},
], max_tokens=300, temperature=0.0)
print(result["text"])
```

Для pipeline вне ноутбука:

```python
from recsys.config import load_config
cfg = load_config(["configs/default.yaml", "configs/gemma.yaml"])
```

`configs/gemma.yaml` включает Gemma для описания выдачи. Разбор запроса остаётся
по правилам; при необходимости включите также `summarizer.type: llm`.
Клиент сохраняет роли сообщений и передаёт `max_new_tokens`, температуру и таймаут.
Для старого внешнего модуля с функцией `function(prompt)` настройте
`llm.gemma_service.path`, `module`, `function` и `chat: false`.

## Обновление кода и управление

Импорт, `%autoreload` и пересоздание `Pipeline` не перезапускают модель.
`ensure_running()` проверяет здоровье и имя модели, повторно использует сервер,
а блокировка предотвращает одновременный запуск двух копий. Сведения о владении
процессом сохраняются вне репозитория; новый клиент может подключиться после
перезапуска ядра ноутбука, если сама ВМ и сервер продолжают работать.

```bash
# Выполнять из корня репозитория на GPU-ВМ.
python llm_gemma_service/gemma_service.py ensure
python llm_gemma_service/gemma_service.py status
python llm_gemma_service/gemma_service.py stop  # только явная остановка
```

Остановка касается только процесса, созданного этим менеджером. Сервер из старого
ноутбука без файла состояния используется повторно, но не останавливается этим
менеджером. После остановки/замены ВМ DataSphere веса придётся загрузить в GPU заново.
Код не обеспечивает работу ВМ 24/7.

`GEMMA_ROOT` и `GEMMA_PORT` переопределяют каталог и порт; задавайте их до импорта,
одинаково для всех клиентов. Прежние значения сохраняются по умолчанию.
Сервер настроен на контекст 2048 токенов, один слот и полную загрузку слоёв на GPU;
смена модели или параметров самого сервера требует явного перезапуска.

## Проверка

Тесты проверяют повторное подключение, одновременные запуски, владение процессом,
передачу сообщений и интеграцию pipeline с подменённым API. Сборка и инференс
на NVIDIA L4 требуют запуска ноутбука в DataSphere.
